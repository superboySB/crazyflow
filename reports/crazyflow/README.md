# ToF PPO 的本机训练与验收

实现与命令见 [主 README](../../README.md)，源项目对应关系见[任务说明](../../docs/tof-parity.md)。本次全部新训练使用 JAX/Flax/Optax PPO、官方 Crazyflow first_principles 参数，最终积分器为官方 RK4。Isaac 只做评测。

机器为 RTX 4070 Ti SUPER，16376 MiB，驱动 580.126.09。GPU 训练关闭预分配，watchdog 每 0.25 s 采样，超过 9728 MiB 计算进程显存则停止；桌面图形进程不计入该进程占用。小于采样间隔的峰值不作为精确测量保证。

## 修复后 GPU 容量

每档均执行 4 次完整 PPO 更新，horizon=120、5 epochs、32 minibatches；后 3 次计算稳态中位数。原始命令和源码哈希保存在 [gpu-capacity.json](gpu-capacity.json)。

| 并行环境 | 计算进程峰值 MiB | 稳态秒/更新 | 交互次数/秒 | 结果 |
| ---: | ---: | ---: | ---: | --- |
| 1,024 | 1,376 | 0.345 | 356,282 | 通过，实测吞吐最高 |
| 8,192 | 5,400 | 4.080 | 240,924 | 通过 |
| 12,288 | 9,706 | 7.065 | 208,714 | 通过，默认并行数 |
| 14,336 | 9,774 | — | — | watchdog 停止 |

12,288 是本次测量中可运行的最大值；环境更多没有提高每秒交互数。快速迭代可用 `--num-envs 1024`，大批量可以使用默认值。计时只涵盖 PPO 更新，首轮编译另记；课程换图和重新编译会影响长运行耗时。容量短测本身不证明后续任意课程密度均可容纳。

## 正式训练与模型选择

从随机网络进行 1,024 环境×120 步×1,000 更新的 PPO 预训练（122,880,000 次交互），再从该完整 Agent 热启动修复后的 ToF 环境，用 12,288 环境×120 步继续训练 100 次更新（147,456,000 次交互）。热启动保留网络、Adam、归一化和策略 RNG，重新创建环境；两阶段使用同一默认机体、任务和随机化配置。

只比较后阶段的 25、50、75、100 更新检查点。验证固定初始两张地图（map_seed=42），使用 seed=9001 重新采样 256 个初态，各统计首个回合，完整 80 s 上限；以成功数排序，成功数相同时比较平均回报。选定后才运行 seed=14001、map_seed=14001 的 256 回合新地图测试，随后在原始 Isaac 场景中与 baseline 配对比较。所有失败保留在分母。

最终交付第 75 更新模型，累计训练 233,472,000 次交互；完整两阶段训练链共执行 270,336,000 次交互。固定地图验证与新地图测试均为 **255/256 成功、1 次碰撞、0 次超时**。新地图成功率 Wilson 95% 区间为约 97.82%–99.93%，平均回合 10.44 s。

最终选择、两阶段计时/显存、验证和独立测试结果记录在 [results.json](results.json)，交付模型是 [`models/crazyflow/policy.npz`](../../models/crazyflow/policy.npz)。报告中的原始训练路径用于追溯训练过程；训练中间模型及完整优化器 checkpoint 已清理，新运行自行写入忽略目录 `outputs/`。

修复后的大批量完整 100 更新用时 941.50 s，计算进程采样峰值 **9,310 MiB**（9.09 GiB），未触发保护；经过 3 次课程换图。前阶段 1,000 更新用时 669.09 s、峰值 1,402 MiB。

成功与唯一碰撞的静态图分别为 [avoidance.png](avoidance.png)、[collision.png](collision.png)，视频保留在本机 `outputs/tof-final-test/`。回放命令和解码检查见 [visualization.json](visualization.json) 与 [render-verification.json](render-verification.json)。

## Isaac sim2sim 配对结果

使用交付模型相同的 SHA256，在未修改的原始 Isaac 任务中运行 seeds 42–46，每种子每策略 32 个初始回合。每对初始地图、位姿、目标、速度、控制器质量/惯量、风和推力随机化记录完全相同，全部十次调用成功退出。

| 策略 | 成功 | 碰撞 | 超时 / 数值失稳 |
| --- | ---: | ---: | ---: |
| 现成 CrazyRL `model_36825.pt` | 155/160（96.875%） | 5 | 0 / 0 |
| 本次 Crazyflow PPO | 132/160（82.5%） | 28 | 0 / 0 |

两者成功率相差 **−14.375 个百分点**；本次实现已完成迁移评测，原 baseline 的成绩仍更高。两个策略训练物理与预算不同；这里比较的是相同目标模拟器和初始场景中的固定策略表现。后续随机噪声按各策略回合/重置进程遵循相同分布，场景配对不表示每个时间点的随机样本都相同。160 回合来自 5 张共享地图，不能视为 160 张独立新地图。

报告、完整 320 行逐回合 CSV、配对场景审计及命令见 [sim2sim/final](../sim2sim/final/)。交付模型在 128 组输入上的 JAX/Torch 推理最大绝对差为 1.073e−6。官方既有 1265/1280 留存结果见 [`baseline-reference`](../baseline-reference/)，与本次 155/160 baseline 的评测预算不同。

## 工程验收

详细证据见 [verification.json](verification.json) 与 [runtime-image.json](runtime-image.json)。

- 完整 CPU 测试：790 passed、45 skipped、16 deselected。跳过项包括需要 GPU 或渲染标记的测试；渲染另行实测。
- 新环境测试覆盖 344/434 维接口、动作单位、奖励手算、深度、自动重置、无物理反传、DR、双地图、默认及实测物理的冻结和 RK4 稳定性。
- YAML 的 GPU/CPU 并行数解析后保存为实际整数。默认映射→同样数量的显式参数恢复逐位一致，改变数量正确拒绝；覆盖实际换图。
- 断点恢复对照：连续两次更新与保存后恢复的策略、Adam、归一化、环境、RNG、地图逐数组一致。把原 TOML 质量从 0.045 改成 0.060 kg 后恢复仍使用冻结的 0.045 kg，结果逐位一致。
- `identify check` 与 `drag-check` 实际运行通过；后者两次优化收敛，合成验证的 roll/pitch RMSE 为 0、R² 为 1。这是软件验收结果。
- MuJoCo：OSMesa/EGL、PNG/GIF/MP4、follow/overview/fpv、Xvfb GLFW、空格暂停与有限帧退出实际验证。
- 交互版 `play`：原生 GPU 窗口通过 13 项控制检查，600 显示帧的持续运行自然结束两个回合并进入第三回合；reset、精确重开和终止帧测距分别验收。截图与本次记录见 [live-play.png](live-play.png)、[live-play.json](live-play.json)。
- 实际 NPZ/PT 接口审计：两个 actor 均接受 344 维观测并返回 4 维原始动作；128 个真实闭环输入的 JAX/Torch 最大差为 `1.43e−6`，详见 [checkpoint-io-audit.json](../sim2sim/checkpoint-io-audit.json)。通道、历史、像素方向及新交互逻辑的 17 项相关 CPU 测试通过。
- 发布训练镜像：不挂载仓库，从已安装包在 CPU/GPU 各执行 3 次 PPO 更新并导出；镜像内源码和交付模型哈希均核对一致，内置模型 8 回合检查通过。
- Isaac 两种模型加载路径：原始 PT 和新 NPZ 均完成原生 GUI/video 450 步，退出码 0；各生成 449 帧、1280×720、15 fps 视频，首/中/末帧解码通过。
- 复制的历史 TensorBoard 事件可读取，HTTP 标量接口返回 35 个标签。

TensorBoard 历史事件位于本地忽略目录 `outputs/sim2sim/tensorboard/`；新日志、视频和 GPU 记录也写入 `outputs/`。Git 仅保留两份模型权重：最佳 Crazyflow NPZ 与官方 baseline PT，配套配置及必要 USD 随代码保留。历史记录路径已规范化，未重跑或修改评测数值，说明见[报告目录](../README.md)。

## 诊断边界

最终模型使用官方 RK4/150 Hz，以避免高增益 PD 与原生电机滞后在 Euler/150 Hz 下的数值振荡，理由和响应数值见[任务对应](../../docs/tof-parity.md)。预训练早于圆柱轴向射线零距离问题的修复；交付候选的训练、模型选择与留出测试全部在修复后进行，旧训练只作热启动来源。圆柱端盖、圆锥线性方程及共线侧面均有回归验证。
